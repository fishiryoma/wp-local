# 事實查核／改寫指南（factcheck_profile.md）

這份檔案定義「事實查核」這個功能該做什麼、不該做什麼。跟 `style_profile.md` 一樣，**這份檔案可以直接編輯**：
覺得查核範圍抓太寬/太窄、或某次結果不符合你的期待，就回來改這裡，下次查核會照新規則走。

查核不是由 `app.py` 自動執行的——是你在 Cowork 對話裡跟 Claude 說要查核某篇文章時，Claude 會先讀這份檔案，
再讀 `factcheck_exports/{post_id}.json`，逐段判斷、上網查證，最後把結果寫進 `sessions/factcheck/{post_id}.json`。

## 這是一個「筆記」功能，不是「校對」功能

事實查核**不會**寫回 WordPress、**沒有**套用/覆蓋原文的按鈕、**沒有**採用/維持原文的打勾打叉機制。
它做的事情就是：把可能過時的地方用刪除線標出來、把建議的新內容或新資訊寫在旁邊、把不確定的地方也寫在旁邊，
讓テスさん自己看著這些筆記，決定要不要動筆、怎麼改寫，然後自己回 WordPress 後台編輯。
所以不需要保守到「沒把握就完全不留痕跡」——多寫一點筆記、多畫一點刪除線，テスさん自己會判斷要不要理它。

## 查核範圍——該查的

只針對「客觀、可驗證、會隨時間過期」的資訊，包括但不限於：

- **價格／費用**：門票、餐點價格、交通票價等
- **營業狀態**：店家是否還在營業、是否搬遷、營業時間是否變更
- **地址與交通方式**：店家/景點位置、怎麼去、最新交通資訊
- **匯率換算**：文中提到的「元（～円）」換算是否還接近現在的匯率
- **統計數字／排行類主張**：例如「大人氣6選」「最受歡迎的3間店」這類清單，其中任一項是否已經不成立
- **法規、稅率、制度**：例如台灣的稅率、勞動法規、簽證規定等會修法的內容
- **活動／展覽日期**：文中提到有時效性的活動是否還在舉辦、日期是否已經過期
- **文章裡的超連結**：確認連結是否還能正常打開（見下面「連結檢查」專節）

同時也**主動找新資訊**：查證過程中如果發現跟這篇文章主題相關、テスさん可能會想加進文章的新東西
（例如同一個地點附近新開的店、同類主題新出現的更好選項、文章沒提到但讀者可能會想知道的更新資訊），
即使原文沒有寫錯任何東西，也可以提出來。**多提不會有損失**——テスさん自己會看完筆記再決定要不要寫進文章，
所以查到有意思的東西不用猶豫，儘量提出來。

## 絕對不碰的內容

- 個人經歷、心情抒發、玩笑吐槽、對話引用、內心獨白——這些是主觀敘述，沒有「對錯」可查證，查核跟這些內容無關
- `style_profile.md` 裡「絕對不改」清單的所有項目：口語語尾、表情符號、目次等結構標題、簽名段落、
  短句節奏、`[ ]` shortcode、半形全形符號等
- **URL 本身**：連結網址一律不直接改寫（見下面「連結檢查」，發現失效只寫筆記提醒，不會自動換成新網址）
- 如果一段文字同時有「事實」跟「個人感想」混在一起，只動事實的部分，感想的部分一個字都不改

## 連結檢查

文章裡每一個 `<a href>` 超連結都檢查一次是否還能正常打開：

- **能打開**：不用特別提，正常結束
- **確定失效**（404、網域不存在、頁面已下架等）：在連結文字所在的那個段落旁邊寫筆記提醒，
  註明是哪個網址失效、建議テスさん自己找新連結或刪掉這個連結。**不要自動把 `href` 改成別的網址**——
  換連結需要テスさん自己在 WordPress 後台動手，這裡只負責提醒。
- **無法確認**（常見於 Facebook、Instagram 等會擋爬蟲/需要登入的平台）：老實寫筆記說明「這個平台會擋自動檢查工具，
  無法確定連結是否還有效，請自行點開確認」，**不要**因為抓不到內容就誤判成「已失效」。

## 輸出方式：段落旁的筆記

查核結果全部用「筆記」呈現，貼在最相關的那個段落旁邊，主要有兩種寫法：

### 1. 直接在文字上畫刪除線 + 寫建議

原文有明確過時的地方、且查到有信心的最新資訊時，把過時的部分用刪除線劃掉，並附上建議的新文字，
一樣要附 `sources`。也可以是新增資訊：不刪東西，直接在段落後面加一句建議新增的內容（一樣要有 `sources`）。
不需要判斷「這個要不要自動套用」，這兩種都只是「劃給テスさん看」，實際要不要改由テスさん自己決定並動手。

新增或改寫的文字，都要維持テスさん原本的日文表達方式與說話習慣（口語、語尾、句子長短），
照 `style_profile.md` 的「絕對不改」規則走——查核跟校對是兩件事，不要順手把文法/用詞也一起改了
（那是「日文校對」分頁的工作）。

### 2. 純文字筆記（沒有具體要劃掉/新增的文字，只是提醒）

以下情況沒有具體的刪除線可畫，純粹寫一則筆記：

- **整篇／整段已經完全過時**：例如介紹的店家已經永久停業、地點已經不存在、整段內容的前提都不成立了
- **查證結果不確定，或找到互相矛盾的資訊**：查得到一些線索，但沒有把握是最新/正確答案，或不同來源講法不一致，
  把查到的線索（含矛盾之處、各自的來源）都寫進筆記，讓テスさん自己決定
- **值得補充但份量太大，無法自然接在既有段落後面的新資訊**（例如需要另外開一個新的小標題／段落才講得清楚）
- **連結失效或無法確認**（見上面「連結檢查」）

## 筆記要附在哪個段落旁邊

每則筆記要指定對應到匯出檔案裡的哪個 `nodes[].index`（貼在文章裡最相關的那一段文字旁邊），
不要放在一個跟內容無關的總覽區塊裡——這樣テスさん读文章時，筆記就在眼睛看得到的地方，不用另外對照。
如果一則筆記牽涉到好幾段（例如整節都過時），就貼在那個段落區塊裡最後一個相關的 node 上。

## 來源與引用規範

- 每一則筆記（不管是刪除線建議還是純文字提醒）都盡量附上 `sources`，讓テスさん自己判斷可信度
- 優先順序：官方網站／政府公告／主流新聞媒體 > 其他來源。找得到官方等級來源就一定用
- 真的找不到官方來源，可以退而求其次引用近期的部落格／評論／社群貼文，但 `sources` 的 `note`
  裡要老實寫清楚「非官方來源」，不要包裝成官方資訊
- `sources` 的 `url` 盡量給可以直接點開的原始連結，不要只給搜尋結果頁

## 查核時的判斷順序（給 Claude 自己核對用）

1. 讀完整篇文章，列出所有「客觀、可能過時」的敘述（對照上面的查核範圍），也留意有沒有主題相關、
   值得補充的新資訊
2. 檢查文章裡每一個超連結是否還能打開
3. 對每一項用 WebSearch 查證現況
4. 把結果整理成一則則筆記，各自對應到最相關的 node index，附上來源
5. 全部處理完才寫入 `sessions/factcheck/{post_id}.json`，不要一邊查一邊寫、寫到一半
